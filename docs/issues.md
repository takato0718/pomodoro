#10 再生位置の保存機能
## 概要
モードが切り替わる際、離れる側のモードの再生位置を保存する（集中 → 休憩、休憩 → 集中の両方）

## 実装内容
- [ ] `getCurrentTime()` で現在の再生位置を取得
- [ ] 離れるモードの `videoId`（または `focusIndex` / `breakIndex`）と再生位置をセットで保存
- [ ] 保存タイミングはモード切り替え時（集中 → 休憩、休憩 → 集中）
- [ ] Player が準備完了してから `getCurrentTime()` を実行

## 参考
- [YouTube IFrame Player API - getCurrentTime()](https://developers.google.com/youtube/iframe_api_reference#getCurrentTime)
- #8 のモード切り替え処理

## 注意事項
- 戻ってきた側のモードの復帰は #11 で行う
- `videoId` のみ保存すると、別モード中に Player の動画が変わった後に復帰できなくなる
- 集中用・休憩用で別々に保存する（`focusResume` / `breakResume`）

## 完了条件
- 集中 → 休憩時に、集中曲の ID と再生位置が保存される
- 休憩 → 集中時に、休憩曲の ID と再生位置が保存される
- Player が準備完了してから実行される

#11 続きから再生機能
## 概要
モードに戻ったとき、保存した位置からそのモードの曲を再生する（集中 → 休憩後に休憩へ、休憩 → 集中後に集中へ）

## 実装内容
- [ ] `seekTo()` で保存した再生位置に移動
- [ ] 保存した `videoId` で曲を読み込んでから `seekTo` を実行
- [ ] `onReady` 後に `seekTo` → `playVideo()` の順で実行
- [ ] 保存データは一度だけ使用し、実行後にクリアする
- [ ] 切り替え先のモードに保存データがある場合のみ実行する

## 参考
- [YouTube IFrame Player API - seekTo()](https://developers.google.com/youtube/iframe_api_reference#seekTo)
- #10 の保存データ構造

## 注意事項
- #9 の「次の曲へ進む」とは別トリガー（こちらはモード復帰時の続き再生）
- `seekTo` が何度も呼ばれないよう、復帰フラグまたは保存データのクリアで制御する
- 集中用・休憩用で別々に復帰する（`focusResume` / `breakResume`）

## 完了条件
- 集中 → 休憩時に、保存した位置から休憩曲が再生される（`breakResume` がある場合）
- 休憩 → 集中時に、保存した位置から集中曲が再生される（`focusResume` がある場合）
- `seekTo` は一度だけ実行される
- 保存データは復帰後にクリアされる
